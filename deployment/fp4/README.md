# FP4 source and recovery recipes

The current departmental installation is the qualified stable-prefix frontend plus retained corrected DFlash/native engine. Use [selected operations](../selected/README.md); these build recipes do not select or rebuild production.

Pinned target/draft downloads, placement, native attention and numerical patches remain unchanged. `scripts/deployment.py prepare fp4 --profile dflash` and `--profile mtp` are explicit isolated rebuild recipes, with one GPU engine enforced and separate prepared profile metadata. A rebuilt image does not inherit binary qualification. The selected image is retained locally.

The compiled native object and full upstream helper source are excluded. Its unresolved licensing notices are documented in [native provenance](native/README.md). Do not assume a download or successful build grants redistribution rights. Exact private recovery software avoids recompilation on this machine.

See [current deployment](../../docs/CURRENT_DEPLOYMENT.md), [qualification](../../docs/FP4_QUALIFICATION.md), and [closeout](../../docs/OPTIMIZATION_CLOSEOUT_20260915.md). Original Ollama, prior FP4 and MTP fallbacks remain explicit recovery choices. No further engine optimization is scheduled.
